# 外部实现修复与程序交付

支持范围是 `mlkem-native` 单编译单元（SCU）源码家族及软件的三个C接口。
本轮扩展覆盖六类完整匹配模式：比较提前结束、由验证结果控制的条件失败路径、数据相关循环、数据相关访存、数据相关条件分支和运行期整数除法。
条件失败路径修复统一计算拒绝结果，并用原实现的 `mlk_ct_cmov_zero` 选择返回结果；其余规则恢复对应规范固定流程写法。所有规则均重新编译并验证正常输出、隐式拒绝规则和返回码。
它不是对任意错误处理或任意程序的自动改写。

## 接入材料

```
your_project/
  src/
    randombytes.c
    mlkem/
      mlkem_native.c
      mlkem_native.h
      mlkem_native_config.h
      src/kem.c
      src/verify.h
      ...其余头文件和源码
  lib/libmlkem512.so
  lib/libmlkem768.so
  lib/libmlkem1024.so
```

1. 实现管理页填写库路径模板和支持的参数集。
2. 源码目录选择 `your_project/src/mlkem`；相邻目录必须有 `randombytes.c`。
3. 选择“源码构建验证：mlkem-native SCU”，选择原构建所用的 `-O3` 或 `-O2`。
4. 软件按固定构建适配器重新编译，并逐参数集比较新库与输入库的SHA256。字节完全相同才启用源码修复；不匹配时继续提供检测能力，但修复保持禁用。
5. 软件记录源码文件清单及摘要。接入后源码或输入库改变时，拒绝使用旧的构建验证结果。

编译配置固定为 GCC、`-fPIC -std=c99 -Wall -Wextra -Wpedantic`、所选优化级别、命名空间 `mlkem` 和对应参数集。
其他源码家族、其他编译参数或带调试信息的构建需要新增适配器。完全一致是保守的接入条件，不一致不代表实现本身有问题。

## 修复和验收

修复页从所选原目标复制源码，在副本应用匹配规则，重新编译三参数集（或用户声明的参数集），每参数集100次流程自测，并执行可用的官方测试向量。
外部库缺少确定性扩展接口时只验证适用的解封装向量，并在报告注明范围。
通过功能验证后，对原库和新库使用同一输入文件、参数集、类别、CPU、配对次数和顺序种子进行复测。
环境预检及相同输入对照不通过时，计时效果只作探索。功能通过与计时改善被支持分别显示。

## 用户获得什么

“导出修复程序”可选择本机保存路径，生成ZIP，包含：

- `src/`：修复后的完整源码；
- `lib/`：服务器实测使用的编译库；
- `repair.patch`：相对原目标的修改；
- `build.sh`：解压后执行 `bash build.sh` 重新编译；
- `build_profile.json`：编译环境、源码与库摘要；
- `verification/repair_comparison.json`：功能及前后计时结论；
- `verification/evidence.zip`：原始计时CSV、图表与证据报告；
- `manifest.json`：交付文件摘要；
- 许可证、接口及构建说明。

交付包不包含实验样本私钥或私有输入二进制。修改库或源码后，需要重新验证才能导出。
服务器库不能保证在其他CPU或发行版直接运行，目标设备应按构建脚本重新编译并重新测试。

## 当前边界

没有源码、不匹配构建配置、未知源码写法、未适配的数据相关寻址或算术、其他循环、汇编实现和复杂异常处理，均需要人工适配。
本轮外部工程来自同一代码基础的三类受控变体，证明接入和交付流程可用，不证明跨所有实现家族通用。
