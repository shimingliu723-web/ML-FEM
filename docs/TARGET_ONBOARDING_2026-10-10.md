# 目标实现接入模块说明

## 工程定位

平台不是只检测自身内置样例，而是把 ML-KEM 实现作为可替换的“目标实现”进行管理。内置目标用于基准验证、对照实验和演示；用户也可以注册自己的 ML-KEM 实现，将其接入同一套样本生成、计时检测、定位、修复和报告流程。

## 输入

注册一个目标实现需要提供：

| 字段 | 说明 |
| --- | --- |
| 目标 ID | 平台内部唯一标识，例如 `custom_mlkem` |
| 显示名称 | 前端展示名称 |
| 类型 | `baseline` / `contrast` / `repaired` / `custom` |
| 参数集 | 支持的 ML-KEM 参数集，例如 `512,768,1024` |
| 动态库路径模板 | 例如 `/path/to/libmlkem{level}.so`，其中 `{level}` 会替换为 512/768/1024 |
| 构建命令 | 可选，例如 `make all` |
| 自测命令 | 可选，用于调用目标实现自带测试 |

## 输出

注册后平台会生成：

- `targets/<目标ID>/target.json` 配置文件；
- 目标列表中的新条目；
- 每个参数集动态库是否存在的检查结果；
- 后续检测、定位、修复和报告流程可直接选择该目标。

## 能力边界

平台对“检测”能力的接入要求较低：只要目标实现能以动态库形式提供兼容调用接口，并能被正式计时程序加载，就可以进入样本生成和时间检测流程。

源码级自动定位和自动修复能力与代码结构相关。当前自动修复规则主要覆盖典型早退比较模式；对源码结构差异较大的外部实现，平台仍可完成时间检测、二进制候选定位和报告输出，但不承诺对所有问题模式自动生成补丁。

## 桌面端使用

打开桌面端后进入“目标接入”页面：

1. 填写目标 ID、名称、参数集和动态库路径模板；
2. 点击“注册/更新目标”；
3. 点击“刷新目标列表”；
4. 在左侧“目标实现”下拉框中选择该目标；
5. 后续在“样本生成”“时间检测”“泄露定位”“报告导出”等页面继续使用。

## 报告建议表述

> 本作品将 ML-KEM 实现抽象为可注册目标。平台内置规范实现、对照实现和修复实现，用于完成基准验证与闭环实验；同时提供用户目标接入能力，允许工程人员将自己的 ML-KEM 动态库注册到平台，并复用样本生成、计时检测、统计分析、定位和报告流程。自动修复模块当前覆盖典型早退比较模式，其他实现可通过定位报告和修复建议进行人工审查或扩展规则。
