# ML-KEM 检测与防护软件（桌面交付）

## 启动与目录

在 Linux 图形会话 / 支持 Linux GUI 的 WSL2 中，从项目根目录运行：

```bash
./run_desktop.sh
```

桌面与计算进程在同一台机器运行，不启动 HTTP 服务，不需要浏览器或登录。
服务器如果没有图形桌面，必须通过图形会话或显示转发查看窗口；计时仍在服务器执行。
`QT_QPA_PLATFORM=offscreen` 仅用于自动化界面验收和实际窗口截图，不是可交互桌面。

首次安装使用 Python 3.10+、GCC、make、binutils、taskset、中文字体与 Qt 系统依赖：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-desktop.txt
.venv/bin/python scripts/prepare_software.py
./run_desktop.sh
```

不能直接跨机器复制 `.venv`；应在目标机器重新安装依赖并编译。默认实验不联网。
普通 Linux/WSL2 可做功能操作；环境预检不通过时，计时结果会标注为探索结果。

## 操作顺序

时间检测的可选“函数级插桩辅助分析”会独立构建诊断库，增加“插桩辅助分析”和“插桩开销”页签。原始检测结论仍只采用原始库数据。诊断库先通过100次流程自测和当前参数集145项ACVP向量，再采集阶段时长。源码与原始库无法验证对应关系时明确拒绝插桩，而不伪造阶段结果。完整适用范围、净开销与空探针成本的区别见 [FUNCTION_TRACE.md](FUNCTION_TRACE.md)。

1. 实现管理：七个内置项为一个规范基线和六类受控机制案例，分别覆盖比较提前结束、条件失败路径、数据相关循环、数据相关访存、条件分支和运行期除法。它们来自同一代码基础，不冒充七套独立算法。
2. 环境自检：选择实际可用 CPU，查看原生 C 固定工作量探针、时钟开销、调度迁移、抖动、系统和频率策略。分级阈值是工程准入策略，不是噪声不存在的证明。
3. 基本功能与向量：选择参数集或全部参数集，运行自测；加载公开向量或输入自有 JSON/JSONL。每条必须给出期望结果才计为正确性通过。
4. 输入样本：每类默认 512 个，四类分别正常、首字节/中间字节/末字节翻转一位。所有输入长度一致。正常生成使用操作系统随机源；固定种子只控制测量顺序，不虚称能重新生成相同密钥。精确复测复用保存的样本。
5. 时间检测：选择样本清单，默认每轮 10000 对、3 轮。先测环境，再做功能检查；每轮先以相同输入进行 A/A 对照，再测正常/变化类别。两组待测输入均在计时外复制到同一64字节对齐缓冲区，以控制输入地址及缓存准备条件。C 程序预热2000对后测量，结束后再次测环境。A/A同样按重复实验判定：只有全部轮次均显著且差值同方向，才认定存在系统测量偏差并降级为探索结果；单轮显著结果完整保留但不单独否决整批实验。主检验仍要求三轮全部显著且同方向。完整保留所有原始计时，不事后删除异常值。
   - 自适应序贯检测根据环境质量逐阶段累积样本，并保存停止原因、证据等级和相对固定方案的样本节省率。
   - 网络噪声验证在四档受控延迟/抖动下分别判断服务端内部计时与客户端 RTT，网络证据不替代本地正式计时。
   - 跨编译验证自动发现 GCC/Clang，以 `-O2`、`-O3`、`-Os` 重建基线和比较案例，并保存完整构建与检测证据；详见 [CROSS_BUILD_VALIDATION.md](CROSS_BUILD_VALIDATION.md)。
6. 代码定位：根据所选案例展示对应源码模式；二进制展示条件跳转、向后跳转、条件移动、setcc、索引访存和div/idiv候选。候选指令须结合源码、函数阶段和重复计时解释，数量本身不等于问题点数量。
7. 修复与对照：对完整匹配的六类适配模式生成独立修复目录，保留原目标。外部源码须先通过逐参数集重编译与输入库SHA256完全一致的验证。所有支持参数集各100次自测和适用公开向量通过后，再用同一数据集、类别、次数和种子复测。显示两类输入的均值、p50/p95和开销。点击“导出修复程序”，选择本机保存路径，取得源码、新库、补丁、构建脚本与完整证据包。
8. 实验报告：选择报告导出 Markdown 和 ZIP。ZIP 包含 JSON、原始计时 CSV、图像、补丁和 SHA256 清单，不包含样本秘密材料。报告内所有轮次可追溯，不只选取最好一轮。

## 外部实现接口

输入是可信的本地 Linux 动态库。接入时复制到软件管理目录，不执行用户输入的构建命令。它必须导出以下 C ABI：

```c
#include <stdint.h>
int mlkem_keypair(uint8_t *pk, uint8_t *sk);
int mlkem_enc(uint8_t *ct, uint8_t *ss, const uint8_t *pk);
int mlkem_dec(uint8_t *ss, const uint8_t *ct, const uint8_t *sk);
```

返回 0 表示函数执行成功；同长度但验证失败的输入应保持 ML-KEM 隐式拒绝语义。
共享结果固定 32 字节。参数集与缓冲区长度：

| 参数集 | pk | sk | ct |
|---|---:|---:|---:|
| 512 | 800 | 1632 | 768 |
| 768 | 1184 | 2400 | 1088 |
| 1024 | 1568 | 3168 | 1568 |

原实现符号不同的，需要编写很薄的 C 包装层并链接到原库。并非任意源码文件无需适配都能接入。
仅有 `.so` 时可做正确性、样本、计时和候选反汇编定位。外部源码修复支持mlkem-native SCU构建适配器及完整匹配的六类模式；详细目录、构建对应验证和导出内容见 [EXTERNAL_REPAIR.md](EXTERNAL_REPAIR.md)。
动态库是可执行代码，只接入本人或团队信任的库。任务进程隔离用于应对加载崩溃，不是代码沙箱。
编译器和优化选项可由接入者填报；未知时报告显示 unknown，不能冒写成 -O3。

批量向量格式（Base64 字符串，以下为字段示意，非真实向量）：

```json
[{"level":"ML-KEM-512","ct":"...","sk":"...","ss":"..."}]
```

对内置目标，软件直接调用所选动态库的确定性接口，逐项验证435项官方向量（每参数集145项）：KeyGen、Encaps、Decaps及输入检查；各条显示数据集、tgId、tcId和比较结论。不能将历史其他程序的435项结果当成本次目标结果。
外部目标若同时提供 `mlkem_keypair_derand(pk,sk,coins64)`、`mlkem_enc_derand(ct,ss,pk,coins32)`、`mlkem_check_pk(pk)`、`mlkem_check_sk(sk)`，也可完整验证435项。没有这些扩展接口时明确退回60项解封装向量（每参数集20项），不计为完整435项通过。随机流程自测单独计数。

## 统计口径与解释

差值定义为修改类减正常类。默认每 200 对形成一个时间块，块内平衡执行先后顺序；至少 5 个有效块时对块均值分析。95% 区间采用对应自由度的 Student-t 分位数。
主判定结合配对差值 t 检验与 Wilcoxon 符号秩检验；不一致时要求复测。忽略配对的 Welch/Mann–Whitney 仅作为附加统计，不混为主结论。
重复同方向差异要求至少 3 轮各自显著且方向一致。没有控制多重比较的族错误率，因此多类别探索不应当作预注册的单一检验。
“修复效果得到本轮支持”要求：功能回归通过、修复前重复差异、修复后各轮主检验不显著、绝对差下降，并且前后环境均通过。条件未满足时照实展示，不自动给出绿色通过。
不宣称任意 ML-KEM 实现均可自动修复，不将本地计时结论推广到网络场景，不以未检出代替常数时间形式证明。

## 验收与证据

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_stats.py'
.venv/bin/python -m unittest discover -s tests -p 'test_software.py'
.venv/bin/python scripts/accept_software.py --phase basic
.venv/bin/python scripts/accept_software.py --phase timing
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/check_desktop.py
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/check_advanced_validation_ui.py
.venv/bin/python scripts/smoke_cross_build_backend.py
```

基础验收：七个内置案例分别完成三参数集100次随机流程自测及适用官方向量验证；外部接入另计。同一套向量在多个案例上运行时按执行次数报告，不称为不同向量数量。
计时验收：七案例各3轮×10000对；八阶段插桩各3轮×10000对。跨构建实验使用GCC 9与Clang 17的-O2、-O3、-Os配置，结果见 [CROSS_ENVIRONMENT_AND_BUILD_VALIDATION_2026-10-13.md](CROSS_ENVIRONMENT_AND_BUILD_VALIDATION_2026-10-13.md)。
生成目录为 `results/software/`；桌面截图来自实际 Qt 窗口渲染。统计测试和功能通过不意味着全部题目创新要求已经获得证明；创新需要单独明确基线与改进指标。
