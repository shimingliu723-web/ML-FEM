# P4 三目标对照复测（检测能力与阴性对照）

对应竞赛题目要求 7（防护效果验证）与要求 8（性能要求）。
参数集 ML-KEM-512，2026-10-07 于服务器 `pc12-ThinkStation-P920` 采集。

> **2026-10-07 修订**：本文最初把 `variant_fixed` 表述为"修复实现"，并据此得出
> "修复后差异消失、修复未引入开销"的结论。经核实，`variant_fixed` 的库文件与
> `mlkem_native_baseline` **逐字节相同**（md5 均为 `0854cb28754e9f2f560246f6d95b11cb`），
> 它是原版的副本而非改造版。因此"修复"这一环节**并不存在**，原表述已删除。

## 1 实验目的

验证两件事：

```text
平台能检出对照实现的差异   ->   同一二进制的两份副本不会被测出假差异
```

这里测的是**平台的检测能力与假阳性水平**，不是"ML-KEM 本身有漏洞"。
规范实现（基线）检不出差异是合理结果，不是失败。

> **本实验不能验证的**：防护改造前后的对比，以及改造引入的性能开销。
> 因为当前仓库里**没有真正的改造版**，见第 2 节与第 6 节。

## 2 三个被测目标（实际只有两组有效对照）

| 目标 | 角色 | 说明 |
|---|---|---|
| `mlkem_native_baseline` | 基线 | 平台默认的 mlkem-native 规范实现，库在 `backend/lib/` |
| `variant_early_return` | 对照 | 含提前返回式比较的对照实现，用于证明平台能发现明显差异 |
| `variant_fixed` | **阴性对照** | **与基线是同一份二进制**，用作空白对照，检验流程不产生假阳性 |

`variant_fixed` 的定性依据：

```bash
md5sum backend/lib/libmlkem512.so targets/variant_fixed/lib/libmlkem512.so
# 0854cb28754e9f2f560246f6d95b11cb  backend/lib/libmlkem512.so
# 0854cb28754e9f2f560246f6d95b11cb  targets/variant_fixed/lib/libmlkem512.so
```

两者逐字节相同，它的三个源文件（`verify.h`/`kem.c`/`verify.c`）与 `core/mlkem-native`
的 diff 也为空。

**这意味着**：仓库里目前**不存在"防护改造"这个动作**。`variant_fixed` 是"发现有人把代码
改坏了，然后保留原版"，不是"把坏版改成好版"。选题文档《最终提交材料清单》第 7 条
（改造版本代码和变更说明）与第 8 条（改造前后复测结果与性能开销表）**目前是空的**。

把同一份二进制当作两个目标来测仍然有价值：它是一次**阴性对照**——如果流程对完全相同的
两份二进制报告出差异，说明管道本身会造假阳性。第 4 节的结果显示没有。

> **前置说明**：`targets/` 目录及其 `build.sh` 目前在服务器工作区里，**尚未提交到仓库**。
> 本报告的原始 CSV 保存在服务器 `results/p4_compare/`（该目录已被 `.gitignore` 忽略）。
> 基线目标的库路径与另外两个不同（`backend/lib/` 而非 `targets/<id>/lib/`），
> 复现脚本里已做映射。

## 3 实验设置

| 项目 | 取值 |
|---|---|
| 主机 | pc12-ThinkStation-P920 |
| CPU | Intel(R) Xeon(R) Gold 6234 @ 3.30GHz，2 路共 32 线程 |
| 内核 | 5.4.0-216-generic |
| 固定 CPU 核 | 0（`taskset -c 0`） |
| 频率策略 | `powersave`（未修改，如实记录） |
| 每轮配对数 | 20000 |
| 轮数 | 5 |
| 计时方式 | `CLOCK_MONOTONIC_RAW`，只包住 `mlkem_dec` 调用；预热由计时程序内部完成 |
| 采样顺序 | **三个目标轮转交叉**，抵消频率/温度漂移 |
| 异常值处理 | 不做事后剔除，全部原始数据参与统计 |
| 输入类别 | 正常密文，以及中间字节翻转一位的等长密文 |

采样顺序为什么轮转：如果把一个目标一次跑完再跑下一个，两次采样之间发生的
频率或负载漂移会全部算到目标差异上。轮转交叉让漂移均摊到三个目标。

## 4 结果（两次独立运行）

### 4.1 检测能力

差值定义为「变化输入 − 正常输入」，单位为纳秒。每轮都做配对分析：
对时间块均值做单样本 t 检验与 Wilcoxon 符号秩检验，块大小为 200 组。

**第一次运行**

| 目标 | 五轮块平衡均值差（ns） | 平均 | 检出 |
|---|---|---|---|
| 平台基线实现 | +2.59 / −7.83 / +2.65 / −2.18 / +9.14 | **+0.87** | **0/5** |
| 对照实现（早退比较） | −276.42 / −271.96 / −212.89 / −264.93 / −285.86 | **−262.41** | **5/5** |
| 阴性对照（同基线二进制） | −3.85 / +4.51 / +24.60 / +5.59 / −4.08 | **+5.35** | **0/5** |

**第二次运行（独立重跑，同参数）**

| 目标 | 五轮块平衡均值差（ns） | 平均 | 检出 |
|---|---|---|---|
| 平台基线实现 | +1.50 / −4.82 / +3.05 / +3.22 / +8.95 | **+2.38** | **0/5** |
| 对照实现（早退比较） | −268.98 / −283.38 / −265.81 / −268.43 / −270.56 | **−271.43** | **5/5** |
| 阴性对照（同基线二进制） | −20.88 / −9.61 / −3.60 / +0.94 / −6.68 | **−7.97** | **0/5** |

对照实现的显著性水平极高（配对 t 检验 p 值在 1e-70 到 1e-90 量级，
Wilcoxon p = 3.96e-18），95% 置信区间在每一轮都明显不含零。

## 5 结论

1. **平台能稳定发现对照实现的差异。** 两次独立运行都是 5/5 轮全部检出，
   差值分别为 −262.4 ns 与 −271.4 ns，量级一致（相差 3%）。
2. **流程不会报告假阳性。** 阴性对照（与基线同一二进制）两次都是 0/5 轮检出，
   平均差值 +5.4 ns 与 −8.0 ns，95% 置信区间均跨零；耗时也落在同一水平
   （30981 / 30950 ns 与 31301 / 31030 ns）。这与"两份二进制相同"的事实一致。
3. **原第 3 条结论已删除。** 原稿称"修复没有引入可测的性能开销"。该结论无效：
   阴性对照与基线是同一份二进制，两者之差恒为零，**不能作为改造开销的证据**。
   改造开销目前**没有数据**，因为不存在改造版。
4. **一个稳定复现的观察：早退比较版本的耗时波动明显更大。**
   对照实现的标准差为 1237 / 1512 ns，而基线是 715 / 604 ns，阴性对照是 608 / 1649 ns。
   提前返回让执行路径长度随输入变化，这一点在两次运行中方向一致，
   也从侧面说明差异的来源确实是执行路径而不是单纯的测量噪声。

## 6 需要注意的边界

- **本实验没有"改造前 / 改造后"的对比数据。** `variant_fixed` 与基线是同一份二进制，
  改造动作尚未发生。选题要求 7/8 所需的"改造版本代码和变更说明"与"改造前后复测结果与
  性能开销表"因此是空的，需要先补一个真正的改造版。
- 本文的结论只对**本次环境与本次输入类别**成立。`powersave` 频率策略下
  绝对耗时在不同轮次之间会漂移约 1%，所以耗时差只能按"同一量级"表述。
- 阴性对照仍偶有波动较大的轮次：第一次运行第 3 轮为 +24.60 ns
  （区间 [−20.08, +69.29]），第二次运行整体标准差达 1648.9 ns。
  这属于测量噪声，不代表流程失效，但也说明**多轮重复是必要的**。
- **未检出差异不能证明实现绝对恒定时间**，只说明在本次样本量与输入类别下没测出来。
- 对照实现是专门准备的演示目标，**不代表 mlkem-native 的实现质量**。
- 本实验用的是「正常密文 vs 翻转一位密文」。这个对比能测出**执行路径长度变化**
  引起的差异（对照实现的情形），但**测不出编译器引入的、只依赖消息位分布的分支差异**——
  因为两类密文解出的消息都近似均匀随机，置位数均值相同，平均差会相互抵消。
  后者需要精心构造的稀疏密文（见 `experiments/clangover-poc/`）。

## 7 复现方式

```bash
# 在服务器项目根目录下
bash experiments/p4_compare/run_compare.sh          # 轮转交叉采样，约 40 秒
python3 experiments/p4_compare/summarize_compare.py # 输出表 1～3 与环境信息
```

可用环境变量覆盖默认参数：`P4_ROUNDS`、`P4_PAIRS`、`P4_CPU`。

原始数据：`results/p4_compare/<目标>-r<轮>.csv`（每行一个配对，含先后顺序），
环境快照：`results/p4_compare/env.txt`。

分析口径全部来自 `backend/stats.py`：块平衡配对估计 + 单样本 t 检验 +
Wilcoxon 符号秩检验；独立样本 Welch / Mann-Whitney 仅作参考，不参与判定。
