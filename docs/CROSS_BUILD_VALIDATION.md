# 跨编译器与优化级别验证

桌面软件的“时间检测”页提供“运行跨编译器 / 优化级别验证”入口。该任务不是读取历史实验，而是在当前机器上执行以下步骤：

1. 自动发现可用的 GCC 与 Clang；
2. 分别使用 `-O2`、`-O3`、`-Os` 编译规范基线和比较提前退出案例；
3. 对每个新生成的动态库执行功能与官方向量验证；
4. 复用同一批 ML-KEM-512 等长样本、同一 CPU 和同一统计流程；
5. 对每个配置运行 A/A 对照和 A/B 配对计时；
6. 保存构建命令、编译器版本、库摘要、逐轮原始报告、汇总 JSON、日志和对比图。

完整矩阵为两种编译器乘三种优化级别，共六种构建配置、十二个目标批次。若机器缺少某个编译器，软件只运行可用配置，并在报告的 `missing_configurations` 中明确记录；此时不得宣称完成完整跨编译器矩阵。

正式统计证据仍要求环境前后检查、固定 CPU、A/A 对照和重复轮次同时通过。跨构建结论只说明当前 CPU、工具链版本、优化级别与样本条件下的稳定性，不能外推到其他处理器架构或网络路径。
