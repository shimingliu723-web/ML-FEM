# 环境自检模块说明

## 目的

环境自检模块用于判断当前运行环境是否适合作为 ML-KEM 解封装高精度计时实验环境。它解决的问题不是“平台能不能运行”，而是“该环境下得到的纳秒级时间结论能不能作为正式实验依据”。

因此平台将应用场景分为两类：

- 功能演示环境：可用于基本功能验证、样本生成、源码/二进制定位、修复流程和报告展示。
- 正式计时环境：应具备 CPU 调度稳定、可固定核心、频率策略可观测、后台干扰较低等条件，用于生成正式计时检测和修复前后对比结论。

## 检查内容

模块位置：

- 后端：`backend/env_check.py`
- 桌面端：左侧导航栏“环境自检”

检查项包括：

1. 基础运行条件：Linux/WSL、gcc、make 是否可用。
2. CPU 固定能力：是否安装 `taskset`，请求 CPU 是否在可用亲和性范围内。
3. CPU 频率状态：是否能读取 `scaling_governor`、当前频率、最小/最大频率。
4. 虚拟化识别：识别 WSL2、VMware、KVM、Hyper-V 等虚拟化环境。
5. 本地抖动探针：执行固定计算负载，统计 p95/median、max/median，用于判断调度与频率漂移是否明显。
6. 正式计时程序：检查 `experiments/formal_timing` 是否已构建。

## 输出等级

模块输出三类等级：

| 等级 | 含义 | 建议用途 |
| --- | --- | --- |
| green | 环境稳定性较好 | 可作为正式计时检测与修复前后对比实验环境 |
| yellow | 平台功能可运行，但存在虚拟化、频率不可控或抖动偏高 | 用于功能演示、流程验证，不建议作为正式计时结论来源 |
| red | 基础依赖不完整 | 需先安装构建/运行环境 |

## 报告建议表述

正式报告中建议使用以下表述：

> 平台的基本功能、样本生成、源码/二进制定位、修复和报告展示可在普通 Linux、WSL2 与虚拟机环境中运行。由于纳秒级计时实验对 CPU 调度、频率策略、虚拟化层和后台负载高度敏感，平台提供环境自检模块，对当前环境是否适合作为正式计时依据进行评估。WSL2 与 VMware 等虚拟化环境可用于功能演示与流程验证；正式计时检测和修复前后对比结论在 CPU 调度稳定、可固定核心、后台干扰较低的 Linux 服务器或真实 Linux 主机上生成。

## 命令行使用

```bash
cd ~/ML-FEM
source .venv/bin/activate
python backend/env_check.py
```

桌面端使用：

```bash
./run_desktop.sh
```

打开左侧“环境自检”，点击“运行环境自检”。
