# 七类机制案例与用户接入边界

本软件内置七个可复现实验项。其中一个是规范基线，另外六个是在同一份规范实现源码上加入的受控机制案例。它们用于验证软件能否完成“正确性验证—样本生成—重复计时—源码/二进制定位—受支持模式修复—同条件复测”的工程闭环，不代表七种互相独立的 ML-KEM 算法。

所有内置项必须先通过 ML-KEM-512、ML-KEM-768、ML-KEM-1024 的随机流程自测及公开向量验证。受控行为不得改变密钥生成、封装和解封装的输出语义。

| 软件项目 | 机制 | 自动定位证据 | 自动处理方式 | 计时解释边界 |
|---|---|---|---|---|
| `mlkem_native_baseline` | 规范固定流程基线 | 完整扫描比较、掩码选择 | 不修改 | 用于 A/A 对照；未检出差异不等于绝对证明 |
| `case_compare_early` | 比较函数提前结束 | 首个不同位置立即返回 | 恢复完整扫描与差异汇总 | 首/中/尾位置变化用于观察处理长度关系 |
| `case_conditional_failure` | 失败处理条件路径 | 验证结果控制两条后续路径 | 两侧工作统一执行，最后掩码选择 | 等长正常类与验证失败类用于比较路径差异 |
| `case_variable_loop` | 数据相关循环次数 | 循环上限由比较汇总结果决定 | 恢复固定流程比较函数 | 受控案例会产生明显工作量差异 |
| `case_memory_index` | 数据相关内存索引 | 比较结果参与表索引 | 移除结果相关表访问并恢复固定流程 | 效果受缓存和处理器影响；源码证据不等于实测显著 |
| `case_conditional_branch` | 数据相关条件分支 | 验证结果直接控制分支 | 移除结果相关分支 | 分支预测可能掩盖或放大差异 |
| `case_variable_division` | 运行期整数除法 | 源码除法表达式与二进制 `div/idiv` | 恢复规范乘法/移位公式 | 指令存在不表示所有处理器上均有可测差异 |

## 用户实现接入

用户可接入导出 `mlkem_keypair`、`mlkem_enc`、`mlkem_dec` 的 Linux 动态库，并可选择提供源码。软件会复制输入库、记录摘要、检查符号并进行功能与向量验证。

自动修改仅在以下条件同时满足时启用：

1. 源码采用已支持的 `mlkem-native` 单编译单元布局；
2. 软件能够按记录的编译配置重新构建；
3. 重建库与用户输入库的 SHA-256 完全一致；
4. 源码中的完整模式与某条适配规则匹配，而不是只命中一个关键词。

不满足条件时，软件仍可完成库级功能验证、计时检测和候选定位，但只输出人工适配建议，不会自动改写文件。

## 证据链

每次实验保存目标库摘要、样本清单摘要、参数集、CPU、编译信息、原始计时 CSV、统计检验、源码片段、反汇编候选、补丁摘要及修复后功能回归结果。普通日志不记录私钥、中间状态、完整输入或验证内部值。

## 函数级插桩

插桩诊断构建统一记录七个解封装阶段：私钥结构检查、内部解密、派生重加密材料、重加密、完整输入比较、拒绝材料派生和最终结果选择；第八个观察点根据所选案例自动放置在对应机制位置。软件同时运行同输入对照，使用八阶段 Bonferroni 阈值，并单独测量八对空探针的参考成本。

插桩库需重新通过100轮功能回归和所选参数集的公开向量验证。阶段结果只用于辅助定位；原始库总时间仍是主检测结果，探针耗时不会从阶段数据中主观扣除。
